# `doctrine/` — the loop's authoritative rules

This directory is Software Factory's own configuration for unattended execution. It is
**deliberately not in the target repository** and **deliberately not in prose-only form**.

```text
doctrine/
  README.md            this file: precedence, integrity, amendment
  DOCTRINE.md          human rendering of every rule (dual-mode: a person can run it)
  loop.json            stage order, attempt cap, hard stops, commit policy, budgets
  agents/models.json   role → tier → `<providerId>/<model>`
  rules/rules.json     rule id → statement → the gate that enforces it
  hooks/hooks.json     stage → hooks executed before/after entering it
  manifest.json        sha256 of every file above, regenerated by `npm run doctrine:manifest`
```

## Precedence and quarantine

`doctrineService.load()` resolves the root from `FACTORY_DOCTRINE_ROOT`, defaulting to this
directory. The loop then enforces, in order:

1. The root must exist and must **not** be inside the target repository (fail closed).
2. Every file's sha256 must match `manifest.json` (fail closed on mismatch).
3. The target repository's instruction files (`AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`,
   `CONTEXT.md`, `.claude/`, `.opencode/`, `opencode.json`, `opencode.jsonc`, `.cursorrules`,
   `.github/copilot-instructions.md`) are recorded with their hashes into the run's quarantine
   manifest and **never read** by the loop.
4. Every process the loop spawns receives `OPENCODE_DISABLE_PROJECT_CONFIG=1`,
   `FACTORY_DOCTRINE_ROOT` and `FACTORY_DOCTRINE_SHA256`, so a harness invoked downstream cannot
   pick up the target's project config either.

A target repository's own constitution governs its domain. It does not govern the loop.

## Integrity

```bash
npm run doctrine:manifest            # regenerate after an edit
npm run doctrine:manifest -- --check # verify; non-zero exit on mismatch
```

`manifest.json` covers every file in this directory except itself. A run records the aggregate
digest in its checkpoint and re-verifies it at `plan` and at `report`, so a doctrine edited
*mid-run* halts the run rather than silently changing the rules under it.

## Amendment procedure

Edit the machine file first, then the document, then the manifest, then run
`npm run verify:loop`. A rule that exists in `DOCTRINE.md` but not in `rules/rules.json` is
documentation; a rule that exists in `rules/rules.json` with no resolvable gate is refused at
load time.
